jeton d'administration

Il est affiché dans la console du studio à son premier démarrage, et conservé dans conversations/_admin.json.

machines

Une machine à agent appelle le studio toutes les dix secondes. Le studio ne l'appelle jamais : elle peut donc être derrière une box, sur un portable, ou sur un réseau qu'on ne maîtrise pas.

retours des utilisateurs

Chaque réponse peut être notée d'un pouce dans l'interface. Un pouce en bas garde la demande, le moteur choisi, les réglages et les paroles : de quoi refaire le cas sans redemander à personne.

clés d'API

Le studio tourne entièrement en local et continue de le faire sans aucune clé. Une clé posée ici n'est qu'une option : si le fournisseur refuse ou tarde, le modèle local reprend la main et le journal de la tâche dit pourquoi. Le nom du modèle est modifiable : les catalogues changent plus vite que ce logiciel.

Contenu adulte : une demande repérée comme telle reste sur cette machine, quel que soit le réglage ci-dessous. C'est vérifié dans le code, pas ici.

comptes

Sans compte, chaque navigateur garde son espace prive, comme avant. Avec un compte, l'espace suit la personne : même historique sur l'ordinateur et sur le téléphone, et deux adresses du même studio (127.0.0.1 et l'adresse réseau) cessent de donner deux historiques séparés.

Un compte créé ici reçoit un mot de passe que l'utilisateur devra changer lui-même : le mot de passe n'est jamais conservé, seule une empreinte l'est, et personne — pas même l'administrateur — ne peut le relire.

aiguilleur

Un classifieur décide seul des demandes qui ne réclament aucune écriture — agrandir, détourer, fluidifier — sans appeler le moindre modèle de langage. Il apprend aussi des demandes que vous validez d’un pouce, ou dont vous imposez le moteur.
